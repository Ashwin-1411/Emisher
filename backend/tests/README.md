# tests/

## 1. Purpose
Unit tests per module, an end-to-end fixture check, and API integration tests. The suite runs with **no network access and no API keys**.

## 2. Where it fits
Exercises everything in `backend/app`. `conftest.py` wires a `Services` object with a static DNS zone, an in-memory cache and an HTTP transport that fails the test on any unexpected outbound request.

## 3. Concepts you need to know
- **Fixtures** (`tests/fixtures/*.eml`) are **synthetic**: invented domains, no real malware or phishing kits. See the table below.
- **Mocked externals**: VirusTotal/urlscan/RDAP use `httpx.MockTransport`; DNS uses `StaticResolver`; sleeps are replaced so retries are instant.
- **EICAR**: a harmless antivirus test string. It exercises the "known malicious hash" override without handling malware; tests assemble it in memory so the repo never contains a file Windows Defender would quarantine.

| `test_scoring.py` | weights, thresholds, overrides |

Fixtures (`fixtures/`):
1. `01_legit` - all checks pass, real DKIM signature
2. `02_display_name_spoof` - "PayPal Support" from an unrelated domain
3. `03_lookalike_punycode` - Cyrillic-"a" domain
4. `04_dmarc_alignment_fail` - SPF passes for another domain, DMARC fails
5. `05_link_text_mismatch` - text shows one URL, href another
6. `06_safelinks` - wrapped links, one hiding a mismatch
7. `07_double_extension` - `invoice.pdf.exe` (a stub that is just `MZ` + zeros)
8. `08_macro_doc` - `.docm` whose only macro is `AutoOpen -> MsgBox`
9. `09_malformed` - broken MIME
10. `10_forged_received` - impossible timestamps / private hop

## 5. Design decisions and why
- **Decision:** Fixtures are generated by `fixtures/build_fixtures.py` and committed.
  **Why:** Reviewable, reproducible; a throw-away DKIM key is regenerated with matching `zone.json`.
  **Alternatives considered:** Hand-written files only.
  **Trade-off:** Re-running the builder changes `01_legit.eml` and `zone.json` together (commit both).
- **Decision:** The macro document is built by a ~100-line OLE writer (`build_office.py`).
  **Why:** Office isn't available and real samples are off-limits.
  **Alternatives considered:** Download a sample (rejected).
  **Trade-off:** Tied to what `olevba` accepts.
- **Decision:** `MockTransport` instead of `respx`.
  **Why:** Built into httpx; handlers can assert on requests.
  **Alternatives considered:** `respx` (installed, usable if preferred).
  **Trade-off:** Slightly more handler code.

## 6. Edge cases and limitations
- No test talks to real Gmail, VirusTotal, urlscan or RDAP; do one live run with keys before relying on it.
- The extension has unit tests for its Gmail helpers only (`extension/tests`); the popup/banner UI is verified manually.

## 7. How to test it
```
cd backend
python -m pytest -q                 # everything
python -m pytest tests/test_auth.py -q
python tests/fixtures/build_fixtures.py   # regenerate fixtures (needs the dev extra: cryptography)
```
From the repo root with make installed: `make test`.
